⚡ Cross-Site Scripting Lab (XSS)

Cross-Site Scripting occurs when an application includes untrusted data in a web page without proper validation or escaping, enabling attackers to execute malicious scripts in victims' browsers (cookie theft, defacement, session hijacking).

🔍 1. Reflected XSS

GET Query

The search parameter ?term= is rendered directly into the HTML response using Jinja2's | safe filter without escaping.

🧩 3. DOM-Based XSS

Client-Side Sink

The client-side JavaScript reads from a source (input or window.location.hash) and injects it straight into an unsafe sink: element.innerHTML = ....

Waiting for DOM insertion...
DOM PAYLOADS:

🛡️ Prevention & Safe Coding

To stop Cross-Site Scripting, always sanitize untrusted input, encode output based on context (HTML body, attributes, JavaScript variables), use textContent instead of innerHTML, and enforce a strong Content Security Policy (CSP).
