OWASP #01 Broken Access Control

🔑 Insecure Direct Object References (IDOR)

IDOR occurs when an application exposes a reference to an internal implementation object (such as a database key ?id=1) without verifying if the requesting user has appropriate authorization to access that object.

👤 Account Profile Query

You are currently logged in as {{ current_username }} (Session ID: {{ current_user_id }}). Notice that you can change the target ID to inspect anyone else's account secrets!

KNOWN USERS IN DATABASE:
{% for u in all_users %} ID #{{ u['id'] }} - {{ u['username'] }} {{ u['role'] }} {% endfor %}
Direct API Route:
/api/user/{{ current_id }} (JSON)

📋 Record Details for User ID: {{ current_id }}

Object directly fetched from SQLite query without session verification
{% if user_data and user_data['role'] == 'administrator' %} 🚨 PRIVILEGED ADMIN RECORD EXPOSED {% endif %}
{% if user_data %}
USERNAME: {{ user_data['username'] }}

User with ID {{ current_id }} does not exist.
{% endif %}
Why this is vulnerable: The server reads request.args.get('id') and queries the database immediately without verifying if session['user_id'] == requested_id or if the session has administrator privileges.

🛡️ Secure Implementation 

# Always enforce authorization checks before returning data
logged_in_user_id = session.get('user_id')
if requested_id != logged_in_user_id and session.get('role') != 'administrator':
    abort(403) # Forbidden
